# digest-collector

Самостоятельный сервис, который собирает общее письмо из готовых AI-дайджестов и отправляет его через Unisender Classic API. Один выпуск всем подписчикам раз в три календарных дня после 10:00 МСК.

## Границы сервиса

```text
Сборщик новостей → PostgreSQL: опубликованные выпуски
                                  ↓
                          digest-collector → Unisender → email подписчиков
                                                 ↑
                                    форма на Club Landing
```

- Существующий сборщик новостей публикует материалы; этот сервис читает только представление `digest.newsletter_issue_source_v1`.
- Club Landing содержит форму подписки. Подтверждение адресов, приветствие, список контактов и отписки обслуживает Unisender.
- Здесь находятся расписание, чтение NewsletterIssue email-period v1, сборка HTML/plain text письма, отправка и журнал кампаний. Нет Next.js, интерфейса сайта, сбора Telegram и повторной AI-генерации.

## Локальный запуск

Node.js 24 и npm:

```sh
npm ci
npm run check
cp .env.example .env
# Заполнить .env. Сам по себе файл не загружается: передать его явно.
node --env-file=.env scripts/worker.mjs --dry-run
node --env-file=.env scripts/worker.mjs --once
node --env-file=.env scripts/worker.mjs
```

В окружении платформы `npm start` запускает постоянный процесс. `npm run once` выполняет один проход; `npm run dry-run` проверяет текущий период без вызовов Unisender и записи в журнал. Без конфигурации `npm start` завершается с `disabled`; это не признак готовности production. Сборка JavaScript не нужна.

## Расписание и доставка

`UNISENDER_FIRST_SEND_DATE` — обязательная начальная дата общего графика в формате `YYYY-MM-DD`. Даты отправки: начальная, +3, +6 дней и далее. С 10:00 до конца соответствующего московского дня процесс может отправить один выпуск за **три предыдущие завершённые даты**. Проверка выполняется раз в 30 секунд. Пропущенные даты не догоняются автоматически.

Материалы с одинаковым `eventId` включаются один раз, сохраняется самая свежая версия. Пустой период записывается как `skipped`. Допускаются дни без опубликованных материалов: письмо включает то, что есть в окне.

Журнал `newsletter.unisender_campaigns` резервирует ключ `(topic, list, send_date, mode)` до запроса провайдеру. Он сохраняет идентификаторы материалов, хеш содержания, ID сообщения и кампании. Тестовая и публичная отправки разделены. После неоднозначного сетевого результата состояние `uncertain` или оставшаяся незавершённая запись блокируют повтор; требуется ручная сверка с Unisender. `accepted` означает принятие кампании провайдером, а не подтверждённую доставку в ящик.

Отправка по умолчанию выключена. Для теста нужны `UNISENDER_CAMPAIGNS_ENABLED=true`, `UNISENDER_ACCOUNT_READY=true` и `NEWSLETTER_TEST_RECIPIENT=digest@irreplaceable-ai.ru`. Другой тестовый адрес блокируется. Для отправки всему списку дополнительно нужен `UNISENDER_PUBLIC_DELIVERY_ENABLED=true` и пустой `NEWSLETTER_TEST_RECIPIENT`. API-ключ остаётся на сервере. По выбору владельца включена стандартная статистика открытий и переходов Unisender; добавление меток GA/Яндекс.Метрики выключено. Unisender подставляет персональную ссылку `{{UnsubscribeUrl}}`.

## База и развёртывание

Два подключения с разными правами: источник только для чтения, журнал — `SELECT/INSERT/UPDATE`. Миграции выполняет отдельный владелец. Секреты задаются в окружении и не коммитятся.

[Пошаговое подключение и Timeweb](docs/deployment.md). Dockerfile запускает тот же процесс от пользователя `node`; HTTP-сервер и публичный домен ему не нужны.

## Проверки

`npm run check` запускает ESLint и `node --test`. PostgreSQL-интеграции включаются при наличии `NEWSLETTER_TEST_DATABASE_URL`; имя БД должно заканчиваться на `_test`. Они создают собственные таблицы, представление и тестовые роли — запускать только на одноразовой базе. GitHub Actions проверяет миграции, ограниченные права, конкуренцию отправщиков и контейнер на отдельном PostgreSQL.

## Готовый выпуск за период

Отправщик читает **один** email-period v1 за точные fromDate–toDate из `digest.newsletter_issue_source_v1`. Topic Digest выполняет редактуру всего периода и сохраняет максимум 8 карточек. Коллектор проверяет контракт, тему и даты, верстает карточки с фото/видеопревью и ссылками на сайты. Telegram URL запрещены контрактом. Все медиа повторно проверяются перед отправкой; одна недоступная картинка не удаляет остальные карточки. Редиректы при этой повторной проверке не разрешены.

`awaiting_issue` означает, что готового выпуска пока нет: worker ждёт следующего тика, журнал не захватывается и Unisender не вызывается. `empty` — готовое редакционное решение без карточек, оно записывается как `skipped`. Ошибки контракта никогда не включают fallback к дневным новостям. Отправленные ранее кампании сохраняют прежние ключи и не повторяются после обновления.

Согласовать `NEWSLETTER_FIRST_SEND_DATE` producer с `UNISENDER_FIRST_SEND_DATE` по трёхдневному циклу. Producer начинает в 09:00 МСК, sender сохраняет свой порог 10:00. Reader получает только SELECT нового view; прежнее разрешение на дневной view можно отозвать после переключения. Runtime не получает owner credential.
