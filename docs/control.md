# Пульт email-дайджеста

Владелец входит в отдельное приложение. На главной выбирает плановую дату выпуска и видит подготовку, передачу в Unisender и статистику доставки. Кнопка предпросмотра открывает готовое письмо. Для действий с пропущенным выпуском выберите его первоначальную дату. Окно ручной отправки начинается в 10:00 МСК в день выпуска, подготовки — в 09:00. Сведения на главном экране обновляются раз в 30 секунд.

## Развёртывание

1. Разверните совместимые версии Topic Digest и Club Digest Sender. Синхронизируйте трёхдневный график и тему обоих сервисов. До подключения панели действующие приложения могут работать с выключенным `NEWSLETTER_CONTROL_ENABLED`. Все SQL-файлы применяет владелец соответствующей базы.
2. В источнике примените миграцию `004_newsletter_control.sql` из репозитория Topic Digest. Выполните `database/newsletter-control-writer-grants.sql` с переменной psql `digest_writer_role` для существующего производителя. Для отдельной роли панели выполните `database/newsletter-control-panel-grants.sql` с переменной `panel_role`. Подготовкой по-прежнему управляет Topic Digest.
3. В журнале отправщика запустите обычный `npm run migrate` с `NEWSLETTER_MIGRATION_URL` (миграции `004-sender-control.sql` и `005-sender-attempt-history.sql`). Выполните `database/control-sender-grants.sql` с переменной `runtime_role` для существующего отправщика и `database/control-panel-grants.sql` с `panel_role` для отдельной роли панели. Сохраните прежние права отправщика на исходное представление. URL роли владельца используется только в миграторе.
4. Включите `NEWSLETTER_CONTROL_ENABLED=true` на производителе и отправщике, перезапустите их по очереди и проверьте появление обеих отметок связи. Постоянный процесс отправщика запускается через `npm start`. На продакшене режим панели, ID списка, тема и начальная дата должны совпадать с настройками отправщика.
5. Создайте **отдельное backend-приложение** Timeweb App Platform с исходниками этого репозитория, в регионе и приватной сети рабочих баз. Для среды Node.js 24 используйте команду сборки `npm ci --omit=dev` и команду запуска `npm run control`. Для Docker можно использовать тот же образ с переменной `DIGEST_PROCESS=control`. Изменять команду или роль уже работающего отправщика для этой цели не требуется.
6. Подключите HTTPS и укажите адрес без завершающего слеша в `CONTROL_ORIGIN`. Направьте HTTP-трафик на `PORT` (по умолчанию 8080), путь проверки процесса `/healthz`. Статусы соединений с базами отображаются отдельно на главной после входа.

### Окружение панели

| Переменная                                                                                                 | Значение                                                                  |
| ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `CONTROL_ORIGIN`                                                                                           | Внешний HTTPS-адрес. Для локальной разработки разрешён HTTP на loopback.  |
| `CONTROL_USER`, `CONTROL_PASSWORD_HASH`                                                                    | Логин владельца и scrypt-хеш пароля                                       |
| `CONTROL_MODE`                                                                                             | Явное `public` или `test`, совпадающее с режимом запущенного отправщика   |
| `UNISENDER_FIRST_SEND_DATE`, `UNISENDER_LIST_ID`, `DIGEST_TOPIC_ID`                                        | Как у отправщика, например тема `ai`                                      |
| `DIGEST_DATABASE_URL`                                                                                      | Отдельная роль панели в источнике                                         |
| `NEWSLETTER_DATABASE_URL`                                                                                  | Отдельная роль панели в журнале                                           |
| `DIGEST_DATABASE_NETWORK`, `DIGEST_DATABASE_SSL`, `NEWSLETTER_DATABASE_NETWORK`, `NEWSLETTER_DATABASE_SSL` | Как в [инструкции подключений](deployment.md), с учётом размещения панели |

Ключ Unisender нужен только рабочему отправщику. Создайте пароль в менеджере паролей. Хеш можно получить в Bash без отображения пароля на экране или в истории команд.

```bash
read -rs -p 'Пароль владельца: ' panel_password
printf '%s' "$panel_password" | npm run --silent control:password
unset panel_password
```

После входа сессия действует восемь часов и заканчивается при перезапуске панели. Для смены пароля обновите хеш в окружении приложения и перезапустите его. Запускайте один экземпляр панели с этой схемой хранения сессий.

## Если письмо задержалось

- **Ошибка подготовки.** Посмотрите причину и время. Проверьте связь с Topic Digest, исправьте проблему и нажмите «Повторить подготовку». Готовый непустой выпуск за сегодня может забрать плановый отправщик.
- **Выпуск готов и кампания ещё не создана.** Проверьте предпросмотр и выберите «Отправить подписчикам». На следующем экране сверьте период, режим и список. Повторный клик и автоматический запуск используют один журнал.
- **Запрос принят или результат неизвестен.** Выберите «Сверить с Unisender». Пульт покажет сведения провайдера, число доставленных писем и время получения статистики. При неоднозначном исходе публичная отправка остаётся заблокированной.
- **Отправка остановилась до передачи кампании или Unisender отклонил запрос до её создания.** После устранения причины подтвердите отправку ещё раз. Журнал сохранит прежнюю попытку.
- **Кампанию отклонили на модерации.** Сверьте результат. Повтор доступен, если Unisender подтвердил отказ и нулевые отправку и доставку, а журнал ни разу не фиксировал отправленных или доставленных писем. При частичной отправке, остановке или отмене уже созданной кампании откройте отчёт. Повтор для такого выпуска заблокирован.
- **Давно нет связи с сервисом.** Откройте соответствующее приложение по ссылке Timeweb, проверьте журналы и перезапустите контейнер. После восстановления связи ещё раз откройте выпуск. Просроченная команда публичной отправки требует нового действия владельца.

Для остановки панели достаточно выключить её приложение. Для отключения обработки ручных команд выключите `NEWSLETTER_CONTROL_ENABLED` на обоих рабочих сервисах. Журнал кампаний сохраняет защиту от повторной отправки.
